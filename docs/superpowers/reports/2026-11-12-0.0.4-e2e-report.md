## 3. 覆盖的行为

### 3.1 Inbox 投递模型（1B / ack 幂等 / dismiss / 水位）

- 同源**两条**未确认条目：第一条推送后冻结，第二条另开并 `continued=true`（面板显示「（消息更新活跃）」）。
- ack 第一条时同源已有第二条：**不 409**；重复 ack 同一 itemId 返回 200/no-op。
- `inbox_dismiss`：
  - `scope=ids` + `allowImportant=true` 清掉指定条目；
  - `scope=filter` + `priorityBelow` 清低优先；
  - `dryRun` 只预览；
  - HTTP `POST /dismiss` 同样生效。
- `pushRevision` 落库：Java 重启后 `pushRevision` 不变、已冻结未确认条目 `pendingPush=0`、不自动重推；新消息仍能推进 push 水位。
- 计数器持久化：`ackConflicts/pushes/repushes/dismissed/recentErrors` 重启后仍可读（drive6b 看到 `pushes=2, dismissed=2`）。

### 3.2 调度与面板预算

- `importantDelaySeconds` 热重载：改成 4s 后实测首批注入 **4.04s**（修复了 0.0.3 里 `DeliveryPolicy` 只构造一次的问题）。
- 同源 debounce：`normalDelaySeconds=3`，第一条后 2s 再发第二条，实测从第二条起 **3.02s** 才推送（等待被重置）。
- `maxCharsPerItem=80`：`inbox_list` 的 `truncatedChars` > 0；消息板仍保留全文。
- 默认值改为 `importantDelaySeconds=3`、`normalDelaySeconds=60`。

### 3.3 DSH 插件持久化 / 恢复

- `bind` 后状态文件写入 `targetSessionId`；`agents.get() ?? agents.resume()` 恢复不在线的会话。
- 插件用 `pushRevision`（而不是 `panel.revision`）去重：同一 push 水位重启后不再注入。
- 心跳 `POST /plugin/heartbeat` 携带 `sessionId/bound/sse/lastPushRevision/lastMcpStartId/lastError/appliedControlId`。
- 服务端 heartbeat 响应携带 `control`；插件应用后回报 `appliedControlId`，服务端清除 pending control。
- watchdog 可手动/自动把 `restore` 控制命令排给插件（drive6c 验证）。

### 3.4 Watchdog

- 12 个探针：`process/disk/db/directory/inboxHttp/inboxBacklog/mcp/qqAccount/qqZombie/dshPlugin/webconnect/config`。
- `/healthz` 恒 200；`/readyz` 在关键组件 DOWN 时 503；`/watchdog` Bearer 保护。
- **断线重连**：`POST /drop` 后 watchdog 在 1s 级重连成功，记录 `reconnectQq` remediation。
- **部署者 QQ 报警**：设置 `deployer.qq` 后断线，watchdog 先重连、再通过统一发送出口给部署者发私聊；实测 payload `[BMA3 watchdog] qqAccount DOWN: DISCONNECTED (bot-1)`。
- `bma3_watchdog_status/probe/remediate` 三个 MCP 工具可用；手动 remediate 绕过健康 gate、仍受冷却限制。

### 3.5 身份 / 目录 / 搜索

- `chat_message.sender_card` / `sender_role` additive 列；入站显示群名片，昵称以 `[昵称:...]` 保留。
- `qq_group_list` 写 `qq-directory.db`；`QqSourceLabeler` 输出 `QQ群 E2E群 (955432692)`。
- `qq_group_members` / `qq_group_member_info` 返回 `card/role/title`；缓存命中后 inbox 行带 `[头衔:大肥鱼]`。
- `qq_person_id/<qq>` 取代 `qq_sender/`；`qq_name/` 已删除（`nicknameRulesAreNotScoreKeysAnymore` 守住了这一点）。
- `qq_search` 可按消息正文、群名、成员昵称/名片/头衔搜索，并给出 `source` / `qq_person_id/<qq>`。

### 3.6 卡片 / 合并转发 / 群邀请

- `json`/`xml` 卡片保留有界 raw + `title/desc/url/bizsrc`；面板只显示 `[卡片] 标题`。

## 4. e2e 中发现并修掉的问题

1. **watchdog 报警顺序**：DOWN 事件在重连前通知，导致 `deployer_alert_skipped reason=no_connected_account`。修法：先跑 remediation，再通知 listener；并把 `QqSendSupport` 的发送加 5s 超时。
2. **手动 remediate 被健康 gate 拦住**：`bma3_watchdog_remediate dshPlugin` 在组件 UP 时返回 `changed:false`。修法：manual 路径跳过 `applies`，仍按 component/cooldown 约束。
3. **群成员排序**：`ORDER BY role DESC` 让 `member` 排在 `admin` 前；改为 `CASE role owner/admin/other`。
4. **`get_config` 视图漏字段**：新加的 `healthPort/maxCharsPerItem/maxFirstPushDelaySeconds/dismiss/deployer/watchdog` 不在 `ConfigView`，`set_config` 的 `effective` 也看不到。已补齐。
5. **群邀请 raw 泄漏**：卡片 raw 里原本保留 `mqqapi://…&token=SECRET`；现在落库前替换为 `[群邀请链接已移除]`。
6. **插件重复注入**：`panel.revision` 去重改为 `pushRevision`；服务端持久化 push 水位。
7. **`DeliveryPolicy` 不热重载**：改成 `Supplier<DeliveryPolicy>`，读取 `RuntimePolicy.weighting()`。
8. **ack 不幂等**：已 ACKED itemIds 从 `ITEM_NOT_FOUND` 改为 200/no-op。
9. **重启测试自身的时间窗**：drive6 在写 restart-state 前没有等 pending 清零，导致保存的 `pushRevision` 落后一轮；已改为先等 `pendingPush=0` 再记录（产品行为本身正确）。

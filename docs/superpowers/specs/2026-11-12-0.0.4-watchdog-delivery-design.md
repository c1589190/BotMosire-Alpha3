## 1. 一句话模型

0.0.4 把「推送」从一个**内存里的竞态**改成一条**可持久化、可观测、可自愈的流水线**：

```
QQ/OneBot 事件 → 消息板（事实源） → Inbox 条目（同源可多条） → 推送水位（pushRevision，落库）
      → SSE 面板 → DSH 插件（持久化绑定/水位，可 resume） → Agent
      ↑                                                                  ↓
      └──────────── watchdog：探针 / 恢复 / 报警 / 维护任务 ←────────────┘
```

三条硬约束：

1. **同源可以有多条未确认条目**（D-043）：推送后条目冻结，后续消息另开一条；面板用「（消息更新活跃）」提示来源仍活跃。
2. **推送是水位，不是内存表**（D-045）：`pushRevision` 与 `frozen_revision` 落库；Java/插件重启不重推已推送内容。
3. **watchdog 只做恢复与观测，不代替 Agent 处理消息**（D-049）：它不读正文、不 ack、不重发 `UNKNOWN` 发送。

## 3. 投递模型（D-043 / D-044 / D-045）

### 3.1 条目状态

`InboxItem` 保留字段：

| 字段 | 语义 |
|---|---|
| `frozenRevision` | 已推送时的 `pushRevision`；`0` = 尚未推送，可继续合并 |
| `continued` | 创建时该来源已有「已推送未确认」条目 → 面板显示「（消息更新活跃）」 |
| `eventRevision` | 最后一次内容变化的 panel revision；冻结后不再变化 |
| `entries` | 有界窗口（条数 + 字符） |

**不变量**

- 同一来源**最多一条未冻结条目**；已冻结条目永不再合并。
- 条目一旦冻结，内容不再变化 → 对该条目的 ack 不会因同源新消息而 409。
- 已 ACKED 条目不再可见；保留行到 retention 清理。

### 3.2 推送水位

- `pushRevision` 持久化到 `inbox_meta.push_revision`，构造时加载。
- `nextDue()` 用 `item.frozen()` 判断已推送，**不再使用内存 `pushedItems`**。
- `flushPending()`：只冻结本轮窗口内、高于 `pushMinPriority` 的条目；`pushRevision++` 并落库。
- `ack` 幂等：已 ACKED 的 itemId 返回 200/no-op；不存在的 itemId 才 400/404；只有「未冻结且内容已变」返回 409。
- 重启语义：已冻结未确认条目不自动重推（strict-once）；Agent 可用 `inbox_items` 看到并通过 `inbox_dismiss` 清理。

### 3.3 活跃标记

新条目创建时若 `store.hasUnackedFrozenForSource(source)`：

- `continued = true`；
- 面板条目头显示 `（消息更新活跃）`；
- `inbox_items` 返回 `active: true`；
- `inbox_get` 返回 `continued: true`。

### 3.4 `inbox_dismiss`（D-042）

```text
inbox_dismiss(
  scope: "visible" | "filter" | "ids",   // 默认 visible
  itemIds?: string[],
  sourcePrefix?: string,                  // 例 qq_group/955432692
  priorityBelow?: int,                    // 严格 <
  priorityAtLeast?: int,
  olderThanSeconds?: int,
  limit?: int,                            // 默认 100，硬顶 500
  dryRun?: boolean,                       // 默认 false
  allowImportant?: boolean,               // 默认 false：priority >= immediateThreshold 跳过
  reason?: string
)
```

返回：

```json
{"matched":12,"dismissed":12,"skippedImportant":2,"remaining":3,"truncated":false,
 "items":[{"id":"itm-…","source":"…","priority":-50,"totalMessages":3,"lastAt":"…"}]}
```

语义：标记 `ACKED`（不删除），清 `pendingSince`，推进 `ackedRevision` 仅作观测；HTTP 对应 `POST /v1/inboxes/{id}/dismiss`。
可选自动策略（默认关闭）：`inbox.dismiss.auto.{enabled,belowPriority,afterSeconds,maxPerRound}`，由 watchdog 维护任务调用同一入口。

## 4. 调度（D-044）

- 默认 `weighting.importantDelaySeconds=3`、`normalDelaySeconds=60`。
- 合并进未冻结条目时**重置**该条目的 `pendingSince`；不同条目仍取最早 due。
- open 条目首次推送硬上限 `inbox.push.maxFirstPushDelaySeconds`（默认 60，0=关闭）：连续活跃的来源也保证第一次注入。
- 合并条目优先级 = open 条目内**最大值**；每次 append 重算。
- **所有未被 `dropBelow` 丢弃的条目都必须最终推送**：`inbox.push.minPriority` 不再是硬静音闸门（保留字段只为旧配置可加载，值被忽略）；低于 `immediateThreshold` 的走 `normalDelaySeconds`（默认 60s）批次。只有 `weighting.dropBelow` 才表示“不注入、不落库”。
- `DeliveryPolicy` 改为 `Supplier`（或并入 `InboxRuntime`），`set_config` 改延迟立即生效。
- 条目超过 `maxDeferSeconds` 不设（由首次推送上限覆盖）；推送后新消息按 1B 另开条目，不会被旧条目拖住。

## 5. 面板预算（D-044）

```yaml
inbox:
  display:
    maxMessagesPerItem: 6      # 1..50
    maxItemsPerPanel: 6        # 1..50
    maxCharsPerItem: 1200      # 100..20000；0=不限
    includeOmittedCount: true
```

- **不设总字符上限**。
- `panelItem()` 从最新条目向前收集，超过 `maxCharsPerItem` 停止；至少保留 1 条（超长时截断正文并加 `…`）。
- `PanelItem` 增加 `truncatedChars`；面板显示 `…（已截断 N 字）`。
- 消息板保留全文；`inbox_get` 返回条目窗口（同样受字符上限）。

## 6. Watchdog（D-049 / D-050）

### 6.1 模块

```text
bma3-watchdog-spi   （JDK-only）
  Health / ProbeResult / Probe / Remediation / RemediationResult /
  MaintenanceTask / WatchdogOptions / WatchdogStore / WatchdogEvent

bma3-watchdog       （core / agentlib / qqconnect / inbox / webconnect，不依赖 app）
  WatchdogEngine / 状态机 / 退避 / 状态落盘
  probes / remediations / tasks / AgentTools
```

`bma3-app` 从 `AppConfig` 构造 `WatchdogOptions` 并装配；watchdog 不 import app 包。

### 6.2 探针

| 探针 | 判定 | 恢复 |
|---|---|---|
| `process` | 进程存活、堆/线程 | 无（记录） |
| `disk` | dataDir 可写、剩余空间 | 报警 |
| `db` | bot.db / inbox.db `SELECT 1` | 报警 |
| `inboxHttp` | `/healthz` 200 + `/status` 200 | 重启 HTTP server |
| `inboxBacklog` | pending 积压 / `nextPushAt` 长期过期 | 报警（不代 ack） |
| `mcp` | `Bma3McpServer` started + TCP/HTTP 401/405 | 重启 MCP（agentlib 需支持 restart） |
| `qqAccount` | 配置账号 connected + `get_status` 应用级探测 | 强制重连（`AccountRegistry.forceReconnect`） |
| `qqZombie` | 半开 socket（connected 但 `get_status` 超时） | 强制重连 |
| `dshPlugin` | 插件心跳年龄 / 绑定一致性 | 设置 control（restore/remind） |
| `webconnect` | 启用时 binary 存在、会话可建 | 报警 |
| `config` | 最近一次热重载成功/失败 | 记录 |

### 6.3 状态与观测

- `<dataDir>/watchdog/state.json`：每组件最近状态、连续失败数、最近恢复时间、计数器。
- `<dataDir>/watchdog/events.jsonl`：环形事件日志（只记 component/code/count/time，不记正文/URL/token）。
- `bma3_watchdog_status`：当前 + 最近 N 条事件 + 计数器。
- `bma3_watchdog_probe`：立即跑指定/全部探针。
- `bma3_watchdog_remediate`：手动触发恢复（写工具，需授权）。
- HTTP：`/healthz`（liveness，恒 200）、`/readyz`（关键组件 DOWN → 503）、`/watchdog`（JSON，Bearer）。
- 健康端口固定：`server.healthPort`（默认 8766，0=随机）。

### 6.4 部署者 QQ 报警（D-049b）

```yaml
deployer:
  qq: ""          # 空=不报警
  enabled: false
```

- 只允许 Agent 用 `set_config` 修改（与其它配置一致）。
- 组件从 UP/DEGRADED → DOWN 时发一条私聊；同一组件冷却 `alertCooldownSeconds`（默认 600）。
- 发送走消息板 + `QqSendSupport` 的统一出口；`UNKNOWN` 不重发。
- 报警正文只含组件名/错误码/时间，不含 token、URL、消息正文。

### 6.5 插件控制面

- 插件每 15s `POST /v1/inboxes/{id}/plugin/heartbeat`：
  `{sessionId, bound, sse, lastPushRevision, lastMcpStartId, lastError, appliedControlId}`
- 服务端在 heartbeat 响应返回：
  `{controlId, action:"restore"|"remind", sessionId, remind, mcpStartId}`
- 插件应用后回报 `appliedControlId`；watchdog 只负责设置期望状态。
- 插件持久化 `<stateFile>`（默认 `~/.dsh/storages/bma3-inbox.json`）：`targetSessionId`、`paused`、`stopped`、`lastPushRevision`、`lastMcpStartId`。
- 插件加载时若有持久化绑定：`agents.get(id) ?? agents.resume({resumeSessionId:id})`，然后启动 SSE；resume handle 由插件 dispose。
- `mcpStartId` 变化时注入一次提醒：「BMA3 已重启，如 MCP 工具不可用请重连」。

## 7. 身份 / 目录 / 搜索（D-048）

### 7.1 消息模型

- `chat_message` 新增 `sender_card`、`sender_role`（additive）。
- 事件解析读 `sender.card` / `sender.role`；`sender.nickname` 保留。
- 显示名 = 群名片（非空）> 昵称；`qq_user_note.displayName` 仍可覆盖。

### 7.2 目录

`<dataDir>/qq-directory.db`：

```sql
qq_group(account_id, group_id, name, member_count, updated_at, PRIMARY KEY(account_id,group_id))
qq_member(account_id, group_id, qq, nickname, card, role, title, title_expire_at, updated_at,
          PRIMARY KEY(account_id,group_id,qq))
```

- `qq_group_list` 成功后写群名；watchdog 维护任务定期刷新（默认 10 分钟）。
- `qq_group_members(groupId, refresh?, limit, cursor)` → `get_group_member_list`，缓存。
- `qq_group_member_info(groupId, userId, refresh?)` → `get_group_member_info`，含 `title`。
- 头衔按需查、缓存 TTL（默认 10 分钟）；不在每条消息上打 API。
- Inbox 来源标签：`QQ群 <群名> (<群号>)`；条目显示 `群名片(昵称)`，有缓存时附 `[头衔:xxx]`。

### 7.3 优先级键（D-048）

- 删除 `qq_name/<子串>`。
- `qq_sender/<qq>` 改名为 `qq_person_id/<qq>`（精确匹配，无兼容别名）。
- `qq_self_name` 保留（它匹配的是 bot 自己的名字，与发送人无关）。

### 7.4 通用搜索

`qq_search`：

```text
qq_search(query, scope="all"|"messages"|"people"|"groups"|"sources",
          sourcePrefix?, accountId?, from?, to?, limit=20, cursor?)
```

- 消息：`chat_message.text` / `sender_name` / `sender_card` 的 `LIKE`，按 `local_seq` 倒序分页。
- 人/群：先查目录，命中后把 `qq_person_id` / `source` 回给 Agent 供配置优先级。
- 返回紧凑摘要（`seq/at/source/sender/snippet`），不返回全文；`truncated` 标记。
- 先用 `LIKE` + 索引；FTS5 中文分词问题留后续。

## 8. 富消息（D-042 / D-047）

### 8.1 卡片（json / xml）

- `Segment.data` 保留有界 raw（≤8KB）+ 提取字段 `title/desc/url/bizsrc`。
- 面板只显示 `[卡片] 标题`；URL 只在 `qq_card_view` / `includeSegments=true` 出现。
- `qq_card_view(fileId)`：返回卡片类型、标题、摘要、http(s) 链接、是否有群邀请信息。
- 群邀请：从 `mqqapi://group/invite_join` 提取 `groupcode`/`msgseq`（ticket 不入库、不进日志）。
- `qq_group_request_list` / `qq_group_request_decide` / `qq_group_invite_accept`：
  `get_group_system_msg` + `set_group_add_request`；失败回退 `llonebot_debug handleGroupRequest`；provider 不支持返回 `UNSUPPORTED`。

### 8.2 合并转发

- `qq_forward_view(fileId, offset=0, limit=50)`：`get_forward_msg`，展开一层；嵌套标 `[嵌套合并转发]`；分页 + `truncated` + `nextOffset`。
- 不把转发正文写入消息板；它是只读视图。

### 8.3 出站文件（D-047）

`qq_conversation_send_file(source, filePath?, providerPath?, fileName?, text?)`

1. `filePath` 必须在 dataDir 下，大小 ≤10 MiB；读字节后尝试 `base64://`。
2. 若 provider 拒绝 base64，尝试绝对路径（同机场景）。
3. `providerPath` 是给「Agent 已用 bash 把文件放到 QQ 机」的场景，原样作为 OneBot `file` 参数；只做长度/控制字符校验。
4. 群聊 `upload_group_file`；私聊 `upload_private_file`；provider 不支持返回 `UNSUPPORTED_REMOTE_FILE`，不静默改发链接。
5. 先写消息板 OUT 行，再三态回写；`UNKNOWN` 不重试。

### 8.4 平台历史（D-046）

> **⚠ 本节已被 [D-056 / `2026-11-13-remote-history-paging-design.md`](2026-11-13-remote-history-paging-design.md) 取代。**
> `count` 上限 1000 → **100**，删除「1000→300→100 降级」，改为 `message_seq` 游标分页；
> 依据：LLBot 的 `GetGroupMsgHistory` 内部固定 30 条一窗、5 路并发，`count=1000` 会瞬间发出 34 个
> `SsoGetGroupMsg` 打死 QQ 客户端 CMD-PIPE，之后连无关 OIDB 命令一起超时
> （[事故调查](../../reports/2026-11-13-llbot-host-freeze-investigation.md)）。以下为历史记录。

`qq_remote_history(chatType, targetId, cursor?, count=20, reverseOrder=true)`

- `get_group_msg_history` / `get_friend_msg_history`；`count` 1..1000。
- **真实 LLBot 证据（2026-11-12）**：`count=100`、`count=300` 正常；`count=1000` 失败/超时。因此客户端按 **1000 → 300 → 100** 降级重试，并记录每次 `action/count/retcode/elapsedMs/messages/outcome`；大页返回空数组也视为需要降级。
- 返回 `messages[]`（messageSeq、sender、text、segments?）、`nextCursor`、`hasMore`、`truncated`、`requestedCount`、`fetchedCount`、`degradedFrom`、`attempts`。
- retcode 1200 → 空页；其它错误带 `errorCode/retcode`；日志只记 action/count/retcode/耗时/条数。

## 9. 工具设计原则（D-044，逐条验收）

1. **默认值优先**：常用路径零参数/最少参数即可完成；高级参数可选。
2. **返回自解释**：稳定字段名、`total/shown/truncated`、必要的 `hint`；不要让 Agent 二次猜。
3. **重数据显式开启**：正文/段/URL/raw 只在 `include*`/`detail` 时返回；列表默认摘要。
4. **分页不静默截断**：`limit` + `cursor`/`offset` + `truncated`。
5. **错误可执行**：`errorCode` + 一句人话 + 一条下一步提示；不带 stack/token/URL。
6. **句柄优先**：`fileId`/`cardRef` 代替裸 URL；URL 只在显式 detail 返回。
7. **批量与过滤**：ack/dismiss 支持数组与过滤条件；写操作尽量幂等。
8. **破坏性操作可预演**：`dryRun` + 结果计数；重要条目默认保护。
9. **三态发送**：`SENT / FAILED_BEFORE_SEND / UNKNOWN`；`UNKNOWN` 不自动重试。
10. **省 token**：列表只回摘要；分页默认小；同一信息不重复返回。

## 10. 不变量 / 验收判据

1. 同一来源可同时存在「已推送未确认」和「新的未冻结」两条；面板都可见（窗口内）。
2. 对已推送条目的 ack 永不因同源新消息 409；重复 ack 返回 200/no-op。
3. Java 重启后，已冻结未确认条目不会被再次推送；未冻结条目按 `updatedAt + delay` 重新计时。
4. 插件重启后，若 `pushRevision` 未变则不重复注入；变了则注入一次当前面板。
5. 同源新消息在等待窗口内会重置该条目 due；不同条目取最早 due；open 条目超过 `maxFirstPushDelaySeconds` 必推。
6. `inbox_dismiss` 能按 `priorityBelow/sourcePrefix/olderThanSeconds` 清理，默认不碰重要条目，`dryRun` 不改变状态。
7. `maxCharsPerItem` 生效后，单条目注入文本 ≤ 上限（至少保留 1 条）；消息板仍保留全文。
8. `qq_name/` 不存在；`qq_person_id/<qq>` 精确匹配；`qq_self_name` 保留。
9. 卡片段能读出标题/摘要/链接；群邀请能拿到 groupId/sequence 并接受；forward 能展开一层。
10. `qq_remote_history` 不发 count>100；失败有 errorCode/retcode/日志。
11. watchdog 能在 QQ 断线后自动重连（本机 fake OneBot 可复现）；`/readyz` 反映关键组件；部署者 QQ 报警走统一发送出口。
12. 所有新工具满足 §9 的原则（参数/返回/分页/错误/幂等）。

## 11. 风险 / 未验证

- 真实 LLBot 的 `upload_group_file` 是否接受 `base64://`、`get_forward_msg` 的 `content` 形状、`get_group_member_info` 的 `title` 字段：全部 `NOT_RUN`，需要真机样本。
- `llonebot_debug handleGroupRequest` 是扩展动作，provider 不支持时只能返回 `UNSUPPORTED`。
- DSH `agents.resume` 会让会话变 live；插件必须正确 dispose，避免会话泄漏。
- `qq_search` 的 `LIKE` 在超大消息板上可能慢；先用索引与 limit 控制，FTS5 留后续。
- 部署者 QQ 报警可能触发真实私聊；本机 e2e 用 fake OneBot 验证 payload，不冒充真实外发。

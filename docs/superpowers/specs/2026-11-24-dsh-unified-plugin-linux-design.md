# Linux DSH 单插件运行工作流

> **草案** · 2026-11-24（UTC+8）· [D-089、D-091](../DESIGN_RULINGS.md)

Linux 用户安装一次 BMA3。一个 DSH 插件入口负责组装 Inbox、BMA3 预设和 JAR 运行时三个内部组件。普通会话可以管理 Inbox 与 JAR，BMA3 会话还可以使用在线 JAR 的业务 MCP 工具。JAR 停机或配置导致启动失败时，Agent 仍可以查阅和修改 `app.yaml`。

「肯定包括」指上一轮讨论的停机编辑 `app.yaml`。首版覆盖 Linux x86_64 和 DSH Web `0.2.2-rc.5`。已有握手、原生 MCP 和 Inbox 解耦的回环证据见[可行性调查](../reports/2026-11-24-dsh-unified-plugin-linux-survey.md)。本稿接续 D-085 的 Linux 安装与进程管理设计，将 D-066 的连接方式调整为 BMA3 预设内自动接入，并沿用 D-088 的日常工具入口。Windows 工作流由后续专题负责。[原托管设计](2026-11-23-dsh-managed-bma3-bundle-design.md) · [工具入口设计](2026-11-23-mcp-daily-tools-design.md)

## 插件边界

安装包使用 `@mosire/bma3-dsh` 包名，在目标 profile 只声明一条入口行 `bma3-plugin`。入口持有三个内部组件及它们的销毁顺序，profile 配置也集中在这条行。组件通过入口持有的接口协作。注册预设时使用宿主原生作用域，动态 MCP 客户端的注册与撤销归该作用域所有。[DSH 预设注册表](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/preset/agent-preset-registry/README.md)

| 内部组件 | 所有权 |
|---|---|
| Inbox | 注册本 profile 的 `/inbox` 和 `bma3_inbox`，管理会话绑定、一个 SSE 客户端的连接与恢复、预览和受保护的 ACK。 |
| BMA3 预设 | 注册原有 ID `bma3`、提示词及已有的预设能力。在其宿主作用域订阅后端变化，挂载与撤销原生 MCP 客户端。 |
| 运行时 | 注册本 profile 的 `bma3_runtime`，管理 JAR 来源、子进程、配置写入及期望运行状态，发布经过验证的后端状态。 |

入口先注册命令、工具和预设，再启动可选的 JAR。运行时发布当前后端的私有快照，携带实例代次、Inbox 地址、MCP 地址及内部凭据引用。Inbox 和预设分别处理连接就绪与失效。旧代次的迟到请求及回调不得向新实例注入、ACK 或发布工具。凭据引用只在插件内部传递。

## 发行与安装

Linux 每个版本只提供 `mosire-bma3-dsh-<版本>-linux-x64-full.tgz` 及其 SHA-256 校验和。包内含插件、Java 21、BMA3 JAR、启动器和镜像清单。默认使用包内镜像。首次加载时校验平台、版本及镜像摘要，安装镜像、初始化缺失的配置并启动。显式选定的来源与已保存的停止意图优先。一键包缺少镜像或镜像损坏时返回镜像诊断，可按升级回退规则恢复上一可用版本。[现有 Linux 打包入口](../../../packaging/build-dsh-bundle.sh) · [DSH 安装契约](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/develop/basic/publish.md)

用 `dsh plugin --profile web add ./mosire-bma3-dsh-<版本>-linux-x64-full.tgz --ignore-scripts` 安装。安装命令把预构建产物加入所选 profile。第一次打开或重启该 profile 时执行 BMA3 启动流程。一键包使用自己的 Java 21，用户无需另装 Java 或手工配置托管端点。

## 日常使用

1. 一键包启动的 BMA3 默认使用动态回环端口和 token 鉴权，首次生成配置的 QQ 账号为空。用户数据与镜像分目录，默认运行根沿用 `$DSH_HOME/bma3/instances/<profile>/`。
2. 用户在目标会话执行 `/inbox bind`。绑定行为、未绑定时的路由、预览及 ACK 按现有 Inbox 契约运行。普通会话的预览提示只提及当前可用的 Inbox 操作。后端离线时可查询状态，已保存的绑定和确认记录供重连时校验和恢复。
3. 需要完整消息板与收发能力时，用户为会话选择 `bma3` 预设。预设先组装人设，MCP 通过鉴权和工具发现后才可用。新版自动挂 `/mcp/daily`，旧 JAR 兼容全量入口。额外入口按需在同一预设内挂载。普通会话可处理预览和会话控制。已经运行的会话遵循宿主的预设选择与版本保留规则。
4. 已有部署可在一键包中显式指定本地 JAR，或连接单独运行的 BMA3。已有单独部署沿用自己的端点和凭据引用。外部服务的启停和文件归原管理方负责，插件可报告连通状态。

首次启动和预设内动态 MCP 挂载复用现有协议。工具的可见性由注册作用域决定。停机时撤销旧工具，已发出的调用按原业务契约结算，发送结果为 `UNKNOWN` 时不自动重发。[DSH MCP 作用域](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/mcp.md)

## JAR 生命周期

| 动作 | 行为 |
|---|---|
| `status` | 返回实际运行来源、JAR 进程状态、MCP 和 Inbox 各自的就绪状态、版本、下一次启动意图及诊断码。启动失败时仍可调用。 |
| `start` | 串行启动或确认现有自有进程。等待启动握手与健康检查后发布后端。Inbox、MCP 各自连接并报告状态。 |
| `stop` | 保存停止意图，撤销会话侧的旧后端连接，关闭控制管道并等待自有进程退出。DSH 重启后仍遵循这次停止。 |
| `restart` | 在同一个队列内完成停旧进程、用已保存配置启动并重接线。原先已停止时直接启动。新进程失败时保留文件并报告失败，供工具继续离线修复。 |
| `inspect_config` / `configure` | 查询脱敏配置，或将修改提交给当前 profile 的启动设置或 Java 应用配置。 |

首次自动启动由启动策略决定。已经记录的显式停止优先于自动启动策略，下一次显式启动成功后保存运行意图。宿主正常退出或卸载时回收进程并保留用户意图与数据。意外退出沿用控制管道 EOF 和实例锁。配置、启停和来源切换共用同一串行队列。运行时只控制本次握手绑定的自有子进程，未能回收时返回明确状态。

## `app.yaml` 在线和离线修改

Agent 用同一个工具提交 `action: configure`、`target: app` 及结构化 `patch` / `unset`。例如普通会话可在 JAR 停机时提交 `{"action":"configure","target":"app","patch":{"weighting.normalDelaySeconds":1800}}`，之后显式启动。目标文件来自当前托管实例。工具另支持 `target: runtime`，修改启动策略或选择用户已配置的运行来源。切换来源在停止状态下完成，重启生效由显式动作决定。

| 当前状态 | Java 编辑路径 | 成功后的反馈 |
|---|---|---|
| 自有 JAR 在线 | 通过已经验证的本机连接调用受限的 Java 配置处理入口，复用现有 `set_config`、配置编辑器和 watcher。插件内部处理认证与结果，工具注册表只收到 `bma3_runtime` 这个管理入口。 | `applied: true` 并报告已热生效、需重启或热加载失败。只有确认进程采纳时才报告热生效。 |
| JAR 停止或启动失败且已释放所有权 | 用当前选定且支持配置协议的 Java 制品执行一次性配置命令。固定启动参数使用同一个配置根及运行环境，通过 stdin 接收有限长度的 JSON，stdout 只返回结构化、脱敏结果。在业务启动尝试读取旧配置之前分流，全程只执行配置事务。 | `applied: true`，生效时机为下次启动。应用继续保持停止。 |
| 在线状态未知、外部进程持有配置，或旧本地 JAR 缺少配置契约 | 返回明确的连接、占用或版本诊断。支持管理协议的旧 JAR 仍可按原协议启停，离线改配置要求支持该入口。 | 返回错误码与已知状态。通过重新查询区分实际未写入与响应丢失。 |

两条路径共享 Java 的候选配置构建、`ConfigLoader` 校验和写入逻辑，同时执行托管启动要求。受支持的监听项或业务项可以修改。托管地址保持回环并启用 token 鉴权，凭据通过已有引用管理。保留未触及的配置项，配置校验失败时原文件不变。映射结构仍可解析时，允许用补丁修复旧配置。YAML 本身无法解析时，支持停机后的显式结构化整份替换，先保存原文件的受保护恢复副本，再校验和写入候选。

写入在同目录创建权限受控的临时文件，使用原子替换。Java 业务启动在读取配置前取得按规范配置路径定位的稳定所有权锁并持有至退出。离线编辑用同一把锁，在线编辑由拥有配置锁的 Java 进程串行提交。运行状态不明时保持失败关闭。新、旧部署接管同一个配置根前应完成旧启动器停写交接。业务配置的 `dataDir` 或 Inbox 标识改变后，下一次启动须再次核验 Inbox 目标及数据库身份，旧记录保留待确认。

现有 `ConfigEditor` 已有候选校验和同目录写入；实现需补齐在线/离线共享的锁与提交语义，确保原子替换不可用时仍保留原文件。在线请求响应丢失后先查询已保存与已生效的状态，再决定是否重试，避免重复提交。[Java 配置编辑器](../../../bma3-app/src/main/java/io/github/c1589190/bma3/app/config/ConfigEditor.java) · [Java 启动入口](../../../bma3-app/src/main/java/io/github/c1589190/bma3/app/Main.java)

## 升级与回退

旧普通包使用原包名升级。旧 `@mosire/bma3-dsh-managed` 包在 profile 停止后卸载，再安装 `@mosire/bma3-dsh` 的新一键包。迁移先识别旧入口和实际后端来源，再映射到唯一入口及其组件配置。保留原运行根、`app.yaml`、数据库、凭据引用、Inbox 绑定、待确认记录和手动停止意图。外部连接及用户提供的提示词路径沿用原有设置。迁移识别旧 BMA3 全局 MCP 行，明确其迁移或撤销位置。未知用户配置或同时存在两个旧包且来源冲突时，显示冲突并保持旧资源可恢复。使用者确认新 profile 只有一条 BMA3 入口及 BMA3 预设内的一套自动 MCP 接线后再启动。

镜像按清单校验摘要，临时解包并验证版本，再激活。同数据格式支持重新启动上一可用镜像。插件和 profile 级回退恢复相匹配的安装包及入口配置。涉及数据格式变更时，先取得一致备份，回退使用相匹配的数据副本。卸载释放运行时及宿主注册，保留实例数据及会话配置。

运行中升级时，DSH 会为已打开会话保留其预设版本。若仍绑定 BMA3 的旧预设作用域缺少原有终端或图片读取工具，插件在预设注册完成后尝试恢复该作用域的原生工具。会话及预设绑定保持原样，已有工具和宿主限制继续生效。解析宿主工具时跳过尚未安装的包，避免 Node 将升级间隙的解析失败留在缓存中。

宿主重启后，Inbox 可能先于 Web 界面恢复绑定会话。恢复时在 Agent 发布前通过宿主注册表挂载会话投影记录的预设，包含首轮前重新选择预设的情形。无法挂载已有预设时保留 Inbox 绑定并报告恢复失败。无预设服务或无预设记录的会话保留原有恢复行为。

## 不变量

- 一键包向目标 profile 提供一条 BMA3 插件入口，最多一个运行时所有者和一个 Inbox SSE。Inbox 与管理入口的可见性独立于是否选择 BMA3 预设。
- BMA3 JAR 业务工具只在 `bma3` 预设作用域内自动注册。在停止、地址变化、连接失效和插件卸载时按实例代次撤销。系统提示词只由预设组件组装。
- 进程控制始终绑定自有句柄，同一运行根和数据目录仍受独占保护。在线与离线配置写入按规范配置路径相互排斥，命令不能指定任意可执行文件、argv 或输出路径。
- 密钥文件保持 `0600`。工具结果、日志和迁移摘要仅含脱敏信息，配置写入接受凭据引用。管理工具按 DSH 宿主权限执行。
- 消息板、ACK 目标验证、Inbox 风险内容恢复和发送状态沿用现有契约。更换连接不得让旧批次跨实例确认。

## 验收判据

1. 干净 Linux Web profile 一次安装一键包，首次加载后用随包 Java 启动 JAR，无需系统 Java。宿主配置只有一条 BMA3 入口。普通与 BMA3 会话均可绑定、接收一条合成唤醒并查询运行时，预览与 ACK 沿用既有契约。
2. BMA3 会话独占提示词与自动 MCP 工具。普通会话调用 `stop`、`start`、`restart` 后，用原有两个会话验证 MCP 按就绪状态撤销和恢复，Inbox 入口始终可访问，不出现重复 SSE 或残留旧代次。退出宿主后自有 JAR 被回收。
3. 普通会话在线修改合法热加载项和需重启项，分别验证即时生效与重启生效。停机时修改 `app.yaml`，确认磁盘更新、无业务进程或监听器启动、下次启动采纳。覆盖启动失败修复、畸形 YAML 恢复、无效补丁原文件完整、互斥并发、外部占用和凭据脱敏。
4. 从普通包的外部连接和本地 JAR、旧整合包各迁移一次，覆盖显式停止意图与待确认记录。核对用户数据、来源和绑定保留，宿主无旧全局 BMA3 MCP 工具，校验失败或升级失败可恢复原组合。
5. 核对 Linux 发行输出只有一种 DSH tgz，内含完整运行镜像。覆盖镜像缺失、损坏、显式选用其他来源，以及同一 profile 升级后手动停止意图继续生效。
6. 运行中的旧 BMA3 会话在插件升级后沿用原有会话及预设。模拟旧作用域丢失终端或图片读取工具，验证同一会话恢复缺失工具，普通会话和被宿主限制的会话保持各自工具面。
7. 用独立的 DSH 进程恢复写盘后的 Inbox 绑定会话。旧会话的创建头记录 Standard，首轮前改选 BMA3。核对原会话标识、历史、BMA3 人设、原生工具和日常 MCP 工具均可用，Standard 会话与全局无 BMA3 MCP 工具。

## 未决问题

原生宿主验证需确认预设版本保留、已有会话中的工具撤销和工具调用权限按上述语义工作。旧本地 JAR 的配置协议通过显式能力协商确认，具体命令名和错误码拼写在定稿时统一。设计范围与验收顺序见[实施计划草案](../plans/2026-11-24-dsh-unified-plugin-linux-plan.md)。

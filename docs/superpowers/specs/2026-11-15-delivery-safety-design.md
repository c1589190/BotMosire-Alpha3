## 2. 方案与取舍

- **A：分批止损（推荐；用户已选择开始）**：先修出站重复风险、发送状态可追踪及 ACK 恢复；QQ 历史分页、转发、面板总预算另批处理。优点是风险边界和回归范围清楚；代价是不能立即解决所有使用反馈。

## 3. 范围与非目标

**范围**：消息板安全持久化出站状态与分片关联；QQ 文本（含回复/私聊/告警）、图片、文件发送三态；文件传输回退边界；插件在已成功注入后持久化并重试 ACK；读取面与故障可观测；相应迁移和测试。

**非目标**：修改旧数据使之看似已成功；对 `UNKNOWN` 自动发送或仅凭文本相似度自动对账；承诺平台级恰好一次；更改 QQ 历史/合并转发、面板总预算或优先级策略；新增定时任务、QQ 空间或远端自动部署；删除历史数据；让 Agent 管理内部幂等键。

## 4. 出站状态与持久化

### 4.1 语义

消息板的出站记录增加持久化状态，至少表达 `PENDING`、`SENT`、`FAILED_BEFORE_SEND`、`UNKNOWN` 与 `LEGACY_UNKNOWN`；入站记录状态为不适用，不可与发送状态混用。`LEGACY_UNKNOWN` 表示历史出站行无可靠状态记录，不等于发送失败，也不等于可自动补发。旧行即使有外部 ID 也不批量推断为 `SENT`；保留所有原数据和序号。

- `PENDING`：该行已在消息板持久化，准备或正在执行发送；写入失败则绝不调用 provider。单实例异常退出后未完成的 `PENDING` 统一保守收敛到 `UNKNOWN`，不得自动重发。
- `SENT`：provider 明确回报成功；外部 ID 可有可无，不因缺 ID 就推断失败。状态与外部 ID 应在同一事务更新；无法持久化结果时，对外不能声称已经可靠落盘，亦不能重发。
- `FAILED_BEFORE_SEND`：仅限能够证明请求没有交给平台执行、不会产生远端发送副作用的情况。一般性超时、断线、未知 provider 非零响应不自动视为可重试。
- `UNKNOWN`：执行结果无法确定，包括超时、连接中断、不能证明未派发的错误及异常退出恢复。保持人工可观察，不自动重发。

状态回写以消息板记录为单位，读历史/消息工具返回状态；原有字段和 `localSeq` 含义不变。错误信息只记录有界错误类别/返回码，不保存正文、凭据或 provider 原始异常文本；部署者告警日志也不得输出包含原始 provider 消息的整段结果。具体 schema、事务接口及兼容构造方式由计划阶段明确；迁移必须可重复执行，保留旧库及读写兼容。恢复 PENDING 须在取得数据目录单实例锁之后、接入新请求之前执行，不得误改仍在发送的活跃操作。持久化应考虑 SQLite WAL 的同步等级、操作系统和存储介质的掉电保障；不得仅凭一次事务提交就无条件承诺断电零丢失。数据库升级不可假装支持旧程序降级写入；升级/回滚策略在实施计划中写清。

### 4.2 分片与重复调用

一次文本操作可产生多片；为同一次调用生成**服务端内部操作标识**，每个实际发送片持久化片序/总数及各自状态。任一片非 `SENT` 后停止发送后续片；读取面能区分已发送和未确定的片。未产生的片不得伪称已发。重复发起一次新的工具调用本身可能是全新意图：本批不靠文本相同或时间窗口自动去重，不要求 Agent 自行构造幂等键，也不承诺防止所有人为重复发送。

### 4.3 文件/图片和超时

- 文件传输方式回退只在能证明上一方式**未产生远端发送副作用**时允许；`UNKNOWN` 立即停止，保留状态和原出站行。provider 非零响应是否足以证明无副作用不得未经证据一律假定；无法证明则保守处理。首次只提供 `providerPath` 的原有用法仍可用。
- 文本、图片、文件均有有界等待；超时不是远端取消，不作自动重发依据。发送附件及关联文本时，附件状态不确定不得悄悄继续发送依赖它的后续内容；调用方得到可辨别结果。
- 改动覆盖已有文本发送共用出口（含部署者告警）以及图片、文件工具；不能绕过消息板或改变账号路由。

## 5. Inbox：已注入与 ACK 分离

### 5.1 恢复记录

插件对成功投递到绑定会话的面板，保存最小待 ACK 记录：Inbox 服务端持久化身份/代际、inbox 标识、目标会话、原始 panel revision、push revision 和实际显示的 item IDs；**不保存面板正文或 token**。记录与注入水位在同一状态快照中原子持久化，保存成功后才允许 ACK；一次最多保留一批待 ACK，其未安全处理前禁止继续注入新面板。服务端 Inbox 身份应持久化于所用 inbox 数据库，普通服务重启保持不变；换库或身份无法确认时，不对旧队列盲目 ACK，显示可处理的异常。数据库快照恢复/克隆可能保留原身份，因此这个身份本身不能检测回滚或复制：备份恢复流程须显式轮换身份，且在身份可疑时停止自动 ACK；不能声称身份字段足以自动识别全部回滚。具体对外身份暴露和受控轮换方式由实现计划确定，不能依赖每次重启变化的 MCP start ID 冒充数据库身份。

成功持久化后，ACK 网络故障/HTTP 5xx/响应丢失采用有界退避重试原目标；条目 ID 缺失或为空时绝不退回 revision-only ACK。只有确认**该记录中的全部条目**均已确认（含幂等已确认）才删除该待 ACK 记录。当前服务端 `ackItems` 只检查请求集合中是否有任一已知 ID，不足以证明所有条目都被确认；需调整服务端契约或返回逐项结果，缺失、已清理、部分成功均须明确可观察，不得把部分 200 当成全量成功。发生 409 或其他不可安全重试错误时保留记录并提示诊断，不去除 revision、不替换 item IDs、不盲目 ACK 新内容；未知或已清理的 ID 不能仅凭不存在就假定已确认。须提供显式人工检查与处置入口，说明放弃记录可能产生重复或遗留条目，不得静默丢弃。绑定、解绑、暂停和重载不能将旧目标待确认内容误发到另一个会话，也不能静默删除记录；ACK 的恢复与重新注入独立。stop/detach 的用户意图须被尊重，重新启动后才恢复自动 ACK。

待 ACK 期间允许服务端继续积累新条目，但插件暂停新的面板注入，防止新 push 带回尚未 ACK 的旧条目。ACK 完成后必须获取或验证新鲜面板，不能直接注入 ACK 前缓存的旧面板。状态文件缺失可按首次安装处理；存在但损坏或版本不受支持时 fail-closed，不清空原文件也不重注入。状态持久化失败必须显式报错，不能表现为已可靠保存；同进程内避免对已返回成功的 followup 重复执行，故障恢复能力在存储不可写时降级并可观测。旧实例卸载与新实例重载的重叠写入不得覆盖新状态；需定义单写者/代际或等效并发控制。状态文件继续按既有安全要求写入，不能输出密钥或正文。

### 5.2 边界与已知限制

`followup` 和本地持久化是不同系统的两个动作：在 followup 已发生但返回失败、或已返回成功但保存成功前进程中断时，仅靠本设计无法判定投递事实。除非真实 DSH 宿主提供经验证的持久幂等契约，否则不承诺严格一次、不擅自确认或重发；诊断中暴露该不确定窗口。已经由旧版成功注入但未留下 item IDs 的历史条目无法安全自动重建 ACK，保留人工查看/处理路径。

本批不改变服务端已冻结条目的 strict-once 推送或窗口排序；冻结窗口是否可能饥饿用回归测试与诊断明确，若需要改排序/投递协议，应另行设计和确认。

## 6. 不变量

1. 每次 QQ 文本、图片或文件消息的潜在发送副作用前，消息板对应出站行及初始状态已持久化；发生无法判定结果时为 `UNKNOWN`，绝不自动重发。本批不改变撤回、群申请审批等其他平台操作。
2. 任意出站项或分片状态持久化失败不产生“已经可靠记录成功”的假象；重启不把未决/历史不确定项改成确定失败或成功。
3. 文件仅在确认上一方式未派发时回退；超时、断线、模糊非零响应不得被包装为可安全重发。
4. 状态和外部 ID 更新具有事务一致性；消息板仍为事实源；入站、旧数据、账号隔离、正文保密不退化。
5. 同一已经确认注入的面板，ACK 重试不得造成重复注入；仅对原服务端身份、原条目与原版本执行 ACK；发生冲突绝不放宽校验。
6. 待 ACK 记录不得含正文、凭据；跨重启可恢复，持久化失败或身份不匹配必须可观测、fail-closed。
7. 不把假服务/回环结果宣称为真实 QQ 或真实 DSH 宿主验证；未知跨系统投递窗口不声称精确一次。

## 7. 验收判据

- A1：模拟文件请求可能发出后断线/超时，结果 `UNKNOWN`；不再调用任何后备路径，重启后仍可查询该状态。仅在可证实未派发时测试允许的回退。
- A2：文本、图片、文件：先落板、再调用 provider；成功、明确未派发、未知结果和消息板写失败分别测试，含已发送但响应丢失、缺少外部 ID、超时与迟到响应。
- A3：在消息板写入后、请求派发前后、响应返回前后分别模拟进程中断；未决记录恢复保守，不能自动发；旧数据库升级两次，旧消息/序号/索引保留，历史出站标为不确定。
- A4：长文本多片第 N 片不确定时停止后续片；各片和内部操作关联重启后可查询；不会将一次新调用误认为旧操作自动重试。
- A5：模拟注入成功且注入水位与待 ACK 记录已成功持久化后，ACK 500/断线/响应丢失、插件重启、ACK 最终成功与重复成功；这些场景中同一面板不因 ACK 重试再注入，原条目 ACK 有界重试且已确认记录最终清除。单独验证 §5.2 的跨系统不确定窗口不得误称精确一次。
- A6：待 ACK 时收到新 push、ACK 409、缺失/部分 ID、状态损坏或写失败、旧新插件实例重叠、绑定变更、服务数据库身份变更及旧版无待确认记录状态均有负向测试；不得跨目标错误 ACK、泄露正文/密钥或伪造已确认；冲突须有可观察的人工处置路径。
- A7：现有 QQ、Inbox、插件相关回归测试通过；记录测试命令、退出码、数量和被跳过项。真实 QQ 发送、真实 DSH 热重载/重启仅在另行具备授权与安全测试目标时执行，否则标 `NOT_RUN`。

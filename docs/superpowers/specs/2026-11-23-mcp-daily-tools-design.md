# BMA3 MCP 日常工具入口

> 状态：已确认 · 2026-11-23（UTC+8）

## 需求与范围

> 目前不管是查看还是Agent报告都说，目前bma3暴露的工具有一些太多了，而且还有不少重复，这是否可以改善？调查一下

> 那么开始吧

会话请求曾同时带上 `bma3` 与 `bma3inspect` 两套 97 个同定义的工具。注册时使用不同名称即可产生两套声明。当前本机 WSL 配置只保留一个原生 BMA3 挂载，故本次在托管接线中保持单一主入口，并在同一个后端上为日常和额外功能提供互补工具集。

## MCP 契约

以原配置 `server.mcpPath` 为基准，共用同一个监听端口：

| 路径 | 内容 | 接入方式 |
|---|---|---|
| `/mcp`（默认） | 现有全量工具 | 独立客户端和既有配置继续使用 |
| `/mcp/daily` | 30 个日常工具，覆盖 QQ 常用收发和本地查询、Inbox、记忆 | 新版托管 DSH 默认以 `bma3` 注册 |
| `/mcp/ops` | 全量中不在日常入口的工具，含配置、凭据、诊断、调试、桌面及低频渠道能力 | 有需要时在适当作用域显式挂载，可与日常入口同时使用 |

自定义路径适用同样后缀，生成子路径时只去掉末尾斜线。各入口使用现有工具实例与业务数据。低频入口是能力划分，鉴权与原入口一致。将全量与日常或低频入口同时挂到同一会话会重复声明工具。

托管就绪协议仍是版本 1，新增可选路径 `mcpDailyPath`、`mcpOpsPath`。DSH 只自动挂一条连接，优先日常路径。旧 JAR 未声明日常路径时继续连接全量路径。`bma3_runtime status` 显示当前工具集及可选的低频入口地址。用户已有外部连接配置与 D-067 的显式挂载方式继续适用。

## 不变量

- 全量工具名称和行为延续。日常与低频工具集无交集，并集为当前实例的全量工具。浏览器、调试等按配置启用的工具仍只在启用时出现。
- 所有入口绑定同一个回环监听，执行相同的 Bearer、请求体限制和精确路径校验。每个入口的 `tools/list` 与 `tools/call` 使用同一个目录及执行授权。
- 所有入口随现有 MCP 生命周期一起启动、停止和重启。ACK、消息板和 QQ 出站确认规则继续由当前业务工具执行。
- 用于查阅的快照和工具只报告路径与工具集等非凭据元数据。自动管理只作用于 BMA3 自己注册的连接。

## 验收判据

- 用同一个进程与端口连接三个入口，验证超集、互补关系、代表性读写工具和越入口调用拒绝，三个入口分别验证 Bearer。已有全量客户端测试通过。
- 验证自定义路径、旧握手回退、新握手优先日常、异常路径拒绝。托管插件连接时只挂一条 `bma3`。
- Windows 和 WSL 上运行回归，使用隔离实例验证 MCP 列表和托管握手。真实 profile 和 QQ 验证按实际执行记录。

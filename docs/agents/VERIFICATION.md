# 验证与证据规则

## 证据等级

| 等级 | 含义 | 怎么写 |
|---|---|---|
| 得证 | 读代码/查库/跑命令确认 | 给 `file:line`、URL，或命令 + rc + 关键输出 |
| 推断 | 有间接证据，未跑通 | 标「推断」+ 依据 |
| 未确认 | 需要一次真实调用 | 标「未确认」+ 验证方法 |
| NOT_RUN | 没跑 | 写 `NOT_RUN`，不写「通过」 |

## 当前可用的验证

初始化期没有产品代码，构建/测试命令不存在。当前只能做：

```bash
# 仓库状态
git status --short --branch

# 文档相对链接与结构（人工或一次性脚本）
# 目前没有 tools/check-docs.py，状态 NOT_RUN
```

`docs/AGENTS.md` 第八节列了人工检查清单。任何自动化脚本落地后，必须在 `STATUS.md` 记录：

- 命令全文；
- 退出码；
- 测试数/检查项数；
- 证据路径；
- 未覆盖项。

## 红线

- 不打印 raw token / Bearer / Cookie；查库只读，不写宿主状态。
- 不在本仓调用继承来源的 Bot MCP 业务工具；真实 QQ/B 站外发必须有人/主 Agent 明确决策。
- `UNKNOWN` 投递不得自动重试，也不得写成「成功」。
- Mock/fake/回环 smoke 不能冒充真实 QQ、真实宿主或真实 B 站验收；没跑就写 `NOT_RUN`。
- 不把「文档链接检查通过」写成「构建/测试通过」；两者是不同证据。
